## Performance rules (read before touching data access or routing)
- **Never self-fetch the API from a Server Component.** No `api.x.$get(...)` in RSC — call the service in-process (`src/server/queries.ts` for shared reads). Each self-fetch was a whole extra serverless invocation.
- **Session is already cached twice**: better-auth `session.cookieCache` (5 min, signed cookie → normally zero DB hits) + `getSession()` from `src/lib/session.ts` (React `cache`, dedupes within one request). Always use `getSession()` in RSC/route handlers, never `auth.api.getSession` directly.
- **Never import `src/server/schemas/generated/schemas/objects` (the barrel)** — it re-exports 500+ schema modules into the serverless bundle graph. Deep-import the single schema file, e.g. `.../objects/TransactionUncheckedCreateInput.schema`.
- **List endpoints are paginated via headers, body shape unchanged.** `GET /api/transactions?limit=&cursor=` → bare array body + `X-Has-More` / `X-Next-Cursor`; `etag()` + `privateNoCache` (`src/server/middleware/cache.ts`) make repeat reads free `304`s. Adding params is opt-in so existing clients keep working.
- **All balance writes are atomic + race-free**: `updateMany` with a `balance: { gte: amount }` guard inside one `$transaction` — never read-then-write a balance.
- **Composite indexes exist for every hot path** (`prisma/schema.prisma`): `(userId, date desc, id desc)`, `(userId, type, date)`, `(userId, category, date)`. Keep the `orderBy: [{ date: "desc" }, { id: "desc" }]` tiebreak so cursor pagination can't skip/duplicate rows.
- **`next.config.ts` has `cacheComponents: true`.** Consequences: `export const runtime`/`dynamic`/`revalidate` are **build errors** in pages *and* route handlers — do not add them. Any `headers()`/`cookies()`/`auth` access in a page must sit inside `<Suspense>` (see the `…Content` async children + `PageSkeleton` fallback pattern in `src/app/*/page.tsx`). `new Date()` in a prerendered server component also errors (see `landing/copyright-year.tsx`).
- Heavy client libraries must be lazy: `jspdf`/`jspdf-autotable` via `await import()` inside the handler (`download-pdf-dialog.tsx`), `PlusPaymentWizard` via `next/dynamic` (`upgradePlusButton.tsx`).

## Testing conventions
- **Browser-API stubs**: `src/test-utils/browser-mocks.ts` provides `stubIntersectionObserver` (controllable instances + `trigger(target, isIntersecting)`), `stubResizeObserver` (instances + `trigger(target)`), `stubMatchMedia(matches)` (with a `change()` helper for reduced-motion toggles), `stubRequestAnimationFrame` (sync `tickAll`), `setWindowScrollY`, `setViewport`. Use these for components that read `IntersectionObserver`, `ResizeObserver`, `matchMedia`, rAF, or `window.scrollY`; call `vi.unstubAllGlobals()` in `afterEach`.
- **State updates from IO/matchMedia callbacks must be wrapped in `act(...)`** — outside React event handlers they are async-batched and won't flush before the assertion.
- **Don't mix `userEvent` with `vi.useFakeTimers()`** — it hangs. Use `fireEvent` + `act(async () => { await Promise.resolve(); ... })` to flush microtasks (see `tests/components/plus-payment-wizard.test.tsx` status-polling suite).
- **`mockResolvedValueOnce` queues leak across tests** — an unconsumed once-value persists after `vi.clearAllMocks()`. Reset (`mockReset`) in `beforeEach` when a suite chains once-values.
- Landing components (auto-video, hero-media, hero-headline, hero-pill, bento, find-card, use-cases, pricing, faq, facts-marquee, nav, footer, reveal, mock-data) are fully covered. The full page is tested via `LandingPageView` (`landing/index.tsx` — sync presentational half, props `{ session }`); the async `LandingPage` wrapper is NOT rendered in tests (jsdom can't await async RSC — same rule as `AccountTab` below). `HeroPill` rotates on a real interval — use `vi.useFakeTimers()` + `act()` to advance it, `stubMatchMedia(true)` to pin the static first word; the offscreen word measurer duplicates word text in the DOM, so pill tests query `getAllByText(word)[0]`. There is no Lenis, no CSS-var motion primitives, and no scroll-progress on the landing anymore — `Reveal` is the only motion primitive.

## Stack
- Runtime: Bun (`bunx`/`bun run`)
- Frontend: Next.js 16 (App Router, `src/`)
- Backend: Hono mounted as a catch-all Route Handler at `src/app/api/[[...route]]/route.ts` (REST, NOT server actions). All backend logic lives in `src/server/`.
- ORM: Prisma 7 (schema at `prisma/schema.prisma`, generated client at `src/generated/prisma` — gitignored). Config in `prisma.config.ts`. `build` runs `prisma migrate deploy` first (non-interactive, applies pending migrations from `prisma/migrations/` to the prod DB via `DIRECT_URL`), then `prisma generate`, then `next build`. `DIRECT_URL` = direct (non-pooled) connection for migrations; `DATABASE_URL` = pooled connection used at runtime by `src/lib/prisma.ts`. On Neon: use the `-pooler` hostname for `DATABASE_URL`, the direct hostname for `DIRECT_URL`. Local dev: both may point to the same local Postgres. **Adapter is host-aware**: `*.neon.tech` → `PrismaNeon` (`@prisma/adapter-neon`, one multiplexed WS connection, `max` from `PRISMA_POOL_MAX`, default 1); anything else → `PrismaPg`. The client is created lazily through a `Proxy`, so importing `@/lib/prisma` never needs `DATABASE_URL` (builds/tests stay green without it).
- Validation/typesafety: Zod via `@hono/zod-validator`. End-to-end typed client via `hono/client` (`src/lib/api-client.ts`), typed against `App` exported from `src/server/index.ts`.
- PDF generation: `jspdf` + `jspdf-autotable` (client-side, used by Download PDF dialog).

## Resources (backend)
- `/api/user` — get/update the authenticated user's profile (`routes/user.ts` + `controllers/user.ts` + `services/user.ts` + `schemas/user.ts`). Currently only the `plus` flag is editable. `GET /api/user` → `{ plus: boolean }` (selects only `plus`, never the full User row). `PATCH /api/user` → `{ plus: boolean }`; schema is `UpdateUserSchema = UserUncheckedUpdateInputObjectZodSchema.pick({ plus: true }).extend({ plus: z.boolean() })` (required boolean — rejects Prisma op objects like `{ set: true }` and missing field). Service throws `"Not found"` → 404 if the user somehow doesn't exist (controller rethrows non-"Not found" errors → 500). `User.plus Boolean @default(false)` on the `User` model (migration `20260719121457_add_plus_to_user`). The `User` model is **not** user-owned in the usual sense (it IS the user) — ownership is enforced by `c.get("user").id` + `findUnique({ where: { id: userId } })` instead of `findFirst({ where: { id, userId } })`.
- `/api/plus` — Budgie Plus subscription checkout via **mock Midtrans QRIS** (`routes/plus.ts` + `controllers/plus.ts` + `services/plus.ts` + `schemas/plus.ts` + `src/lib/midtrans.ts`). Three authed endpoints + one public webhook: `POST /api/plus/checkout` → 201 `{ orderId, qrString, status, expiresAt }` (creates a PlusOrder + Midtrans mock QRIS transaction); `GET /api/plus/status/:orderId` → `{ transactionStatus, plus }` (ownership-scoped, polls Midtrans status, syncs PlusOrder); `POST /api/plus/simulate-payment/:orderId` → `{ transactionStatus }` (**MOCK ONLY** — simulates the user paying via e-wallet, transitions pending→settlement, grants `User.plus = true`; remove when wiring real Midtrans — the webhook replaces it); `POST /api/plus/webhook` → `{ ok: true }` (**public, NO requireAuth** — Midtrans calls this server-to-server; verifies signature via `src/lib/midtrans.ts`, on settlement grants Plus). The `PlusOrder` model (`@@map("plus_order")`, migration `20260720000000_add_plus_order`) tracks `{ orderId, userId, amount, status, paidAt }`. `src/lib/midtrans.ts` is the **mock Midtrans client** — every function is marked `// === MOCK: replace with midtrans-client ===` and mirrors the real Snap-Bi API shape (`createQrisTransaction`, `getTransactionStatus`, `verifyWebhookSignature`, `parseWebhookNotification`). To integrate real Midtrans: `bun add midtrans-client`, replace each function body with the corresponding SDK call, remove `simulatePayment` + the `/simulate-payment` route, keep everything else unchanged. Pricing: mock Rp 24.500 first month (50% off), Rp 49.000/month regular (`PLUS_PRICING` in `services/plus.ts`).
- `/api/budgets` — full CRUD (`routes/budgets.ts` + `controllers/budgets.ts` + `services/budgets.ts` + `schemas/budget.ts`). One budget per `(userId, category)` — `@@unique([userId, category])` enforces it; service throws `"Budget for this category already exists"` → 409 on clash. Schema picks `{ category, amount, periodDays }` (no `title`, no `currency` from the client — `currency` defaults to `"IDR"` in the schema). `category` is `z.enum(EXPENSE_CATEGORIES)`, `amount` is `z.number().positive()`, `periodDays` is `z.number().int().positive()` (1=daily, 7=weekly, 30=monthly, or any custom N). No balance/account linkage — budgets are category-level spending limits tracked against `prisma.transaction.aggregate` of expense txns in the trailing `periodDays`.
- `/api/subscriptions` — full CRUD (same 3-layer pattern: `routes/subscriptions.ts` + `controllers/subscriptions.ts` + `services/subscriptions.ts` + `schemas/subscription.ts`). One subscription per `(userId, name)` — `@@unique([userId, name])` enforces it; service throws `"Subscription with this name already exists"` → 409 on clash. Schema picks `{ name, amount, currency, category, periodDays, startDate, active }`; `category` is `z.enum(EXPENSE_CATEGORIES)`, `amount` positive, `periodDays` positive int (7=weekly, 30=monthly, 365=yearly), `startDate` is `z.coerce.date()`, `active` defaults `true`. Subscriptions are recurring charges — name + amount + billing cycle, independent of transactions (no auto-deduct; the UI shows next billing date computed from `startDate + ceil((now-start)/periodDays)*periodDays` via `nextBillingDate` in `src/lib/budget.ts`).
- `/api/balance-accounts` — full CRUD (same 3-layer pattern)
- `/api/transactions` — list/getOne/create/delete (no update/edit). **List is cursor-paginated**: `GET /api/transactions?limit=100&cursor=<id>` clamps `limit` to 500 (`src/lib/limits.ts`), always returns a **bare array** (legacy clients unaffected) and puts pagination in headers — `X-Has-More: true|false` + `X-Next-Cursor: <id>`; omit both params for the legacy "everything" behaviour. `GET` routes are wrapped in `etag()` + `privateNoCache` (`src/server/middleware/cache.ts`) so a repeat with `If-None-Match` is a free `304`. Ordering is `[{ date: "desc" }, { id: "desc" }]`, matching the `(userId, date DESC, id DESC)` index. Create & delete run inside a Prisma `$transaction` that **auto-updates `BalanceAccount.balance`** (income +amount, expense -amount, transfer: source -(amount+adminFee), dest +amount; delete reverses) using **conditional `updateMany` writes**: `where: { id, userId, balance: { gte: amount } }` — the guard *is* the insufficient-balance check, so there is no read-then-write race and no negative balance. Errors: `"Account not found"`/`"Destination account not found"` → 404, `"Insufficient balance"` → 400. `Transaction` has optional FK to `BalanceAccount` (source) + `toBalanceAccount` (transfer destination), `onDelete: SetNull` so deleting an account preserves history. Schema uses `z.enum(["income","expense","transfer"])` + `z.enum(ALL_CATEGORIES)` (premade per-type lists from `src/lib/categories.ts` — users cannot type custom categories) + `.refine()` for transfer validation + `.refine()` for per-type category validation.
- `/api/chat` — **AI assistant** (Vercel AI SDK v7 + Google Gemini 2.5 Flash). NOT a Hono route: a dedicated Next.js Route Handler at `src/app/api/chat/route.ts` (a static route takes precedence over the `[[...route]]` Hono catch-all). POST streams a `streamText` response via `result.toUIMessageStreamResponse()`; auth is better-auth `getSession` directly (401 if absent). Tools live in `src/server/chat/tools.ts` (`createChatTools(userId)` factory) and **call the existing services directly** — they never import Prisma themselves (read: `get_balance_accounts`, `get_transactions`, `get_budgets`, `get_subscriptions`, `get_insights`; write: `create_transaction` — returns `{ ok, transaction | error }`, guarded by a system-prompt rule that the model must have explicit user intent first). Schemas in `src/server/chat/schemas.ts`, system prompt in `src/server/chat/system.ts`. Env: `GOOGLE_GENERATIVE_AI_API_KEY` (Google AI Studio key). **Model fallback**: `src/lib/chat-models.ts` — `MODEL_CHAIN = ["gemini-2.5-flash", "gemini-3.5-flash-lite"]` (each model has its own free-tier quota bucket); the client sends `body.model` (allowlisted by `resolveModel`); on a rate-limit error (`isRateLimitError` — matches 429/quota/RESOURCE_EXHAUSTED) `ChatView` auto-downgrades via `regenerate({ body: { model } })` and shows a "lighter model" notice; the chosen model persists in `budgie.chat.{userId}.model` (12h validity, reset by New chat). **AI-call optimization**: `prepareMessagesForApi` (`src/server/chat/prepare.ts` — last-10 window, strips old tool/reasoning parts), `stopWhen: stepCountIs(3)`, `maxOutputTokens: 640`, thinking budget 256 on the primary (`thinkingConfigFor`) / disabled on lite, compact tool outputs (transactions default limit 10). See `ARCHITECTURE.md` §22.

## Conventions
- Backend routes are Hono sub-apps registered in `src/server/index.ts` with `app.route("/x", x)` — start each chain with `.use("*", requireAuth)`.
- Auth: `requireAuth` middleware (`src/server/middleware/auth.ts`) gates every router. Controllers read `c.get("user").id` and services scope every Prisma query by `userId`.
- App schemas live in `src/server/schemas/` — `.pick()` public fields (exclude `userId`) then `.extend()` overrides. Export `Create*`/`Update*` Zod schemas + inferred types.
- Services are pure TS (no Hono, no Context). First arg is always `userId: string`. Only services import `@/lib/prisma`. Ownership checked via `findFirst({ where: { id, userId } })` before mutate (exception: `/api/user` uses `findUnique({ where: { id: userId } })` since the resource IS the user).
- Prisma singleton: `src/lib/prisma.ts` — **lazy `Proxy`**, global-cached, host-aware adapter (`PrismaNeon` on Neon, `PrismaPg` otherwise). Never construct a `PrismaClient` elsewhere.
- Do not use Server Actions for backend logic — use Hono routes.
- Server Components read the DB **in-process** — `prisma` directly for page-specific queries, or the React-`cache`d helpers in `src/server/queries.ts` (`getAccountsForUser`, `getPlusForUser`). Mutations go through the `api` client from a `"use client"` component (cookies auto-attached in the browser). If a Server Component ever *must* call `api`, remember `hc`'s `fetch` does NOT forward incoming cookies — pass `{ headers: Object.fromEntries(await headers()) }`, and always guard `res.ok` + `Array.isArray(data)`.
- Pages that need session/data use the `Suspense` + async-child pattern: outer page renders `PageShell` + `<Suspense fallback={<PageSkeleton variant="…"/>}><XContent/></Suspense>`, and `XContent` awaits `getSession()` (redirecting to `/sign-in` if absent) before touching data. This is what lets `cacheComponents` prerender a static shell. `PageSkeleton` is **per-route** (`variant` mirrors the real geometry — never reuse a generic rows shape for a new route).
- `PageShell` has a `flush` mode (`/chat` only): no page padding, `h-[100dvh] overflow-hidden`, clears the mobile tab bar. The mobile bottom tab bar's height is the shared `--app-tabbar-h` token (`calc(3.5rem + env(safe-area-inset-bottom, 0px))`) — pages clear it with `pb-[calc(var(--app-tabbar-h)_+_1.5rem)]`, never a hardcoded value. `viewportFit: "cover"` (`src/app/layout.tsx`) is required for the safe-area `env()` to be non-zero on iOS.
- SVG reveal animations: never combine `stroke-dasharray`/`pathLength` with `vector-effect="non-scaling-stroke"` (dashes resolve in host space → dotted line, the sparkline bug). `Sparkline` uses a `clip-path` wipe (`.spark-reveal`) on measured pixel geometry; `AssetGrowthCard` uses the `.bar-grow` `scaleY` transform.
- `AccountTab` (`src/components/account-tab.tsx`) is an **async RSC** that takes `{ userName, userId }`, reads `plus` via `getPlusForUser` (no HTTP) and renders `<AccountTabView plus={...} userName={...} />`. `AccountTabView` is the exported **sync presentational** component — test that, not the async wrapper (React Testing Library can't `await` async server components in the jsdom client environment).
- `SignOutButton` lives on the **profile page** (`src/app/profile/page.tsx`), not the sidebar. The sidebar is navigation-only (no auth controls).
- `UpgradePlusButton` (`src/components/upgradePlusButton.tsx`) has two modes: when `plus === false` it lazily renders `<PlusPaymentWizard>` (the 3-step QRIS checkout Dialog, a `next/dynamic` chunk) — tests must `await screen.findByText("Upgrade to Plus")`; when `plus === true` it renders a `Downgrade` button that PATCHes `api.user.$patch({ json: { plus: false } })` directly (no payment flow for downgrade).
- **Public landing page** — `src/app/page.tsx` is a **public RSC** (NO `requireAuth`, NO Prisma, NO Hono) that renders `<LandingPageView session={false} nav={…}/>` from `src/components/landing/` at `/`. Only the session-aware nav streams in (`<Suspense>` around `LandingNavLive`), so the whole marketing surface is a static shell. It is the unauthenticated marketing surface; the auth-gated app routes (`/dashboard`, `/budget`, `/transactions`, `/profile`, `/chat`) are entirely separate and start at those routes. The landing page is NOT part of the 3-layer backend or the type-safety chain — it's static marketing + SEO (rich `metadata` + JSON-LD: WebApplication, BreadcrumbList, FAQPage, VideoObject). `AutoVideo` (`src/components/landing/auto-video.tsx`) is the only `<video>` element in the repo — a "use client" component that renders muted + loop + playsInline, poster-tint fades in, and respects `prefers-reduced-motion` (no autoplay under reduce). Its mp4 source is a hosted Vercel-Blob URL (`BudgieDemo` — the same clip embedded in `README.md`) and is listed **first**; the webm source is an optional local drop-in at `/videos/brand.webm` (listing it first used to 404 on every visit). Landing video assets drop into `public/videos/` (specs in `public/videos/README.md`); missing assets never break the page (poster stays). See `ARCHITECTURE.md` §21 + `UI_DESIGN.md` §16.
- `src/lib/midtrans.ts` is the **mock Midtrans QRIS client**. Every function is marked `// === MOCK: replace with midtrans-client ===` and mirrors the real Snap-Bi API shape. To integrate real Midtrans: `bun add midtrans-client`, replace each function body with the SDK call, remove `simulatePayment` + the `/api/plus/simulate-payment` route, keep everything else unchanged.
- Formatting helpers in `src/lib/format.ts`: `formatRupiah`, `formatBalanceInput`, `formatDate`, `formatTime` (am/pm), `formatDateTimeLocalValue`.
- Premade categories in `src/lib/categories.ts`: per-type lists (`INCOME_CATEGORIES`, `EXPENSE_CATEGORIES`, `TRANSFER_CATEGORIES`), `CATEGORIES_BY_TYPE` lookup, `ALL_CATEGORIES` for `z.enum`. Shared by transaction + budget + subscription schemas. Users cannot type custom categories.

Category→icon element helper in `src/lib/category-icon.tsx` (`categoryIcon(category, className)` returns a ReactElement — must NOT return a component type/class, or `react-hooks/static-components` lint errors).
- Auth clients: `src/lib/auth.ts` is the better-auth **server** instance (prismaAdapter, email/password + Google + GitHub, 5-min session `cookieCache`); `src/lib/session.ts` exports the React-`cache`d `getSession()` used by every page. `src/lib/auth-client.ts` is the better-auth **browser** client (`createAuthClient()`) imported by "use client" components for `signIn`/`signOut`. Dashboard query/chart helpers in `src/lib/dashboard.ts`   (`computeMonthlyNet`, `computeYearNetEffect`, `computeStartingAssets`, `computeGrowthData`, `computeActiveMonths`, `computeAccountNetThisMonth`, `computeNetWorthDelta`) — pure TS, no Prisma/Hono, unit-tested (`tests/lib/dashboard.test.ts`). `src/lib/font-size.ts` (`dynamicFontSize(text)` → a Tailwind text-size class by digit count: ≤7→`text-6xl` … >14→`text-3xl`, used by the dashboard net-worth hero).
